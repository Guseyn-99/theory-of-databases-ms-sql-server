# Транзакции и блокировки в T-SQL

## Слайд 16. BEGIN TRANSACTION + COMMIT

Что это: Транзакция - это группа команд, которые выполняются как единое целое. COMMIT — подтверждает изменения.

Зачем: Чтобы если на середине что-то упадет, база не осталась в «полусломанном» состоянии.

![Скриншот](screenshots/01.png)

## Слайд 17. ROLLBACK

Что это: ROLLBACK — откат транзакции. Все изменения внутри неё отменяются, как будто их не было.

Зачем: Если в середине транзакции произошла ошибка — можно всё отменить.

![Скриншот](screenshots/02.png)

## Слайды 18-19. SAVE TRANSACTION (точки сохранения)

Что это: Позволяет откатить часть транзакции, а не всю. Создаётся метка, к которой можно вернуться через ROLLBACK TRANSACTION метка.

Зачем: Если в длинной транзакции одна операция неудачная — можно откатить только её, а не всё.

![Скриншот](screenshots/03.png)

## Слайды 22-23. @@TRANCOUNT (вложенные транзакции)

Что это: @@TRANCOUNT — системная переменная, которая показывает уровень вложенности транзакций. BEGIN увеличивает на 1, COMMIT уменьшает на 1.

Зачем: Понять, сколько транзакций сейчас активно. Используется в хранимых процедурах.

Зачем: Понимать, почему иногда транзакции падают с ошибкой 1205.

Идея: Окно А читает данные. Окно Б делает DELETE, но не коммитит. Окно А пытается прочитать снова — и зависает в ожидании (потому что строка заблокирована транзакцией Б).

Вывод: READ COMMITTED снимает разделяемую блокировку сразу после выполнения SELECT, поэтому параллельная транзакция может изменить данные. Блокировка не удерживается до конца транзакции (в отличие от REPEATABLE READ).

## Слайд 49. READ COMMITTED — Тест 2 (неповторяющееся чтение)

Цель теста: показать, что при уровне изоляции READ COMMITTED один и тот же запрос внутри одной транзакции может давать разные результаты, если параллельная транзакция закоммитила изменения между двумя чтениями.

**Ход выполнения:**

- Окно А: SET TRANSACTION ISOLATION LEVEL READ COMMITTED → BEGIN TRAN → первое чтение COUNT(*) = 13.

- Окно Б: BEGIN TRAN → DELETE строки 128-1 → COMMIT TRAN (изменение зафиксировано).

- Окно А: повторное чтение COUNT(*) в той же транзакции = 12.

- Окно А: COMMIT TRAN.

## Слайд 55. SERIALIZABLE

**Что демонстрируем:**

SERIALIZABLE — самый строгий уровень. Он блокирует не только строки, но и диапазон ключей. Это значит, что другая транзакция не может ни изменить, ни вставить новые строки в прочитанный диапазон, пока первая не закоммитится.

**Главное отличие от REPEATABLE READ:**

- REPEATABLE READ → блокирует только прочитанные строки (вставлять можно).

- SERIALIZABLE → блокирует весь диапазон (вставлять нельзя).

## Слайды 64-65. SNAPSHOT

**Что демонстрируем:**

SNAPSHOT-транзакция видит данные на момент своего начала. Другая транзакция может вставлять/изменять данные — первая этого не увидит, пока не закоммитится.
